# AGENTS.md

## Project summary

Task Tracker Backend is a small monolithic FastAPI application for creating, listing, retrieving, updating, and deleting tasks. It includes a static Kanban-style frontend at `frontend/index.html`.

Although `README.md` describes direct SQLite access, the current implementation stores tasks in an in-memory Python dictionary (`app/storage.py`). Data is therefore not persistent across process restarts. Treat the code as the source of truth and flag this documentation mismatch when relevant.

## Stack and supported commands

- Python 3.11 is used by the Docker image (`Dockerfile`).
- FastAPI, Uvicorn, Pydantic v2, python-dotenv, pytest, and httpx are pinned in `requirements.txt`.
- The frontend is a standalone HTML/CSS/JavaScript file that calls the API at `http://localhost:8000`.

Supported setup and run commands from `README.md`:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload
```

Supported test command, based on the included pytest tests and dependency:

```bash
pytest
```

Supported container build and run commands: not confirmed. A `Dockerfile` exists and exposes port 8000, but no repository documentation specifies the intended commands.

## API behavior and business rules

Source: `app/main.py`, `app/models.py`, `app/storage.py`, and `app/business_rules.py`.

### Task fields and defaults

- `id` is generated as a UUID when a task is created.
- `created_at` and `updated_at` are UTC timestamps generated by the server.
- `title` is required, is trimmed, must not be blank, and must be at most 200 characters.
- `description` defaults to an empty string.
- `status` defaults to `ToDo`.
- `priority` defaults to `Medium`.
- `assignee` defaults to `null`.
- Create and update payloads reject unknown fields.
- `TaskCreate` does not accept server-managed fields such as `id`.
- `TaskUpdate` does not accept server-managed fields such as `created_at`.

### Allowed values

- Statuses: `ToDo`, `InProgress`, `Done`.
- Priorities: `Low`, `Medium`, `High`.

### Status-transition rules

Only these transitions are allowed:

- `ToDo` → `InProgress`
- `InProgress` → `Done`
- `Done` → `InProgress`

All other transitions, including transitions to the same status, return HTTP 422.

### Endpoint behavior

- `POST /tasks` returns 201 with the created task.
- `GET /tasks` supports optional `status` and `priority` filters.
- `GET /tasks/{task_id}` returns 404 if the task does not exist.
- `PATCH /tasks/{task_id}` applies only supplied fields and refreshes `updated_at` when there is at least one update. Missing tasks return 404.
- `DELETE /tasks/{task_id}` returns 204 on success and 404 when the task does not exist.
- `/health` and `/version` are registered routes; their complete behavior should be checked in `app/routes/` before changing them.
